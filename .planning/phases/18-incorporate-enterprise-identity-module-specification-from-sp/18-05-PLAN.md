<objective>
Implement the SCIM 2.0 Users subset with bearer authentication, idempotent provisioning, and the critical offboarding path.
</objective>

<threat_model>
T-18-04 SCIM bearer bypass: every SCIM endpoint must reject missing or wrong bearer before provisioning logic. Mitigate with first-position middleware and constant-time comparison.

T-18-03 offboarding only advisory: SCIM `active:false` and DELETE must call enterprise revoke/status logic that invalidates live sessions.
</threat_model>

  <action>
    Implement:
    - `POST /Users`: call `enterprise.linkIdentity`; set `scimId` if needed; duplicate external subject returns existing resource with one binding; emit `scim.provisioned`
    - `GET /Users/:id`: resolve by SCIM id, return 404 SCIM error when absent
    - `GET /Users?filter=...`: support filters for `userName eq "..."` and `externalId eq "..."`
    - `PATCH /Users/:id`: apply supported replace operations; `active:false` calls `enterprise.setStatus(..., 'deprovisioned')`
    - `PUT /Users/:id`: full replace of supported attributes; `active:false` deprovisions, `active:true` sets active
    - `DELETE /Users/:id`: call `enterprise.unlinkIdentity({ mode: 'revoke' })`; emit `scim.deprovisioned`

    Unsupported filters or operations must return a SCIM 400 error instead of silently doing nothing.
  </action>
